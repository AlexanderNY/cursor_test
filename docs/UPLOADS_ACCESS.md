# Доступ сервисов к папкам с картинками

## S3-хранилище (рекомендуется)

При включённой настройке Core загружает файлы в **S3-совместимое хранилище** (MinIO по умолчанию на **172.20.10.200:9000**).

- **Endpoint по умолчанию:** `http://172.20.10.200:9000` (задаётся в `core/config.py` как `S3_ENDPOINT_URL`).
- Чтобы включить S3, в Core (переменные окружения или `.env`) задайте:
  - `S3_ACCESS_KEY` и `S3_SECRET_KEY` — ключи доступа к бакету;
  - при необходимости переопределите `S3_ENDPOINT_URL`, `S3_BUCKET` (по умолчанию `uploads`), `S3_USE_SSL=false` для MinIO.
- В S3 попадают загрузки: **VK** (`vk/uploads/`), **Telegram** (`uploads/tg/`), **Threads** (`uploads/threads/`), **Instagram** (`uploads/instagram/`), **Дзен** (`uploads/dzen/`).
- Если S3 не настроен (пустые ключи), Core сохраняет файлы локально в `uploads/<сервис>/` и отдаёт их через HTTP (как раньше).

## Где хранятся изображения (при отключённом S3)

| Путь | Кто пишет | Кто читает |
|------|-----------|------------|
| `uploads/tg` | Core (Telegram Integration UI), tg-bot (сообщения из Telegram) | tg-bot (публикация), Core (GET /tg/uploads/ для превью в UI) |
| `uploads/threads` | Core (раздел Threads) | — (пока только Core) |
| `uploads/url` | Core (curl/screenshot_base64), url-bot (скриншоты) | — (пути в БД; файлы не читаются другими сервисами по диску) |
| `uploads/vk` | vk-bot (конфиг есть) | vk-bot publisher пока не использует локальные файлы (attachments=None) |

## Тома в docker-compose

| Сервис | Том | Путь в контейнере | Итог |
|--------|-----|--------------------|------|
| **core** | `tg-bot-uploads` | `/app/uploads` | Пишет в `/app/uploads/tg`, `threads`, `url`. Доступ к tg общий с tg-bot. |
| **tg-bot** | `tg-bot-uploads` | `/app/uploads` | Читает/пишет `/app/uploads/tg` — **общий с Core** ✓ |
| **url-bot** | — | — | Пишет в `UPLOAD_DIR/uploads/url` (внутри контейнера). **Нет тома** — с Core не делится. |
| **vk-bot** | — | — | Есть `UPLOADS_DIR`, **нет тома** — файлы только внутри контейнера. |
| **wp-bot** | — | — | Умеет `upload_media(file_path)`, но **нет тома** — доступа к общим картинкам нет. |
| **collector**, **processor** | — | — | Работают только с путями в БД, файлы по диску не открывают. |

## Ответ: все ли сервисы имеют доступ?

**Нет.** Общий доступ к папкам с картинками есть только у пары **Core ↔ tg-bot** для `uploads/tg` (один том `tg-bot-uploads:/app/uploads`).

- **url-bot**: сохраняет скриншоты у себя в контейнере; Core сохраняет `uploads/url` в свой том. Пути в БД могут указывать на файлы, которые лежат в разных контейнерах — при необходимости «отдать» скриншот другому сервису нужен общий том или API.
- **vk-bot**: том для uploads не подключён; публикатор пока не прикладывает локальные картинки.
- **wp-bot**: том не подключён — читать файлы из Core/tg-bot/url-bot не может; для постов с картинками нужен либо общий том, либо загрузка по URL.

## Рекомендации

1. **uploads/tg** — уже настроено: Core и tg-bot используют один том.
2. Если нужно, чтобы скриншоты url-bot были доступны Core (или наоборот) — добавить общий том, например `url-uploads:/app/uploads` для Core и url-bot, и писать/читать `uploads/url` из одного места.
3. Если wp-bot будет публиковать посты с локальными картинками — подключить ему тот же том, что и Core (например `tg-bot-uploads:/app/uploads` или отдельный `shared-uploads`), и разрешать пути относительно `/app/uploads`.
