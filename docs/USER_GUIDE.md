# Руководство пользователя CopyParse

CopyParse — платформа для сбора, обработки и публикации контента в соцсети и CMS из единого веб-интерфейса.

Базовый URL: ваш деплой (локально http://127.0.0.1:8100 или https://www.copyparse.ru).

Встроенная справка в приложении: раздел **Справка** (`/about`) — блоки может править администратор.

---

## 1. Вход и профиль

1. Откройте **Sign up** — логин, email, пароль.  
2. Подтвердите email кодом (если включена верификация).  
3. **Sign in** — вход; токены хранятся в браузере, API ходит через Gateway с JWT.  
4. **Profile** — смена email/пароля, выход, выход со всех устройств, вкладки биллинга и статистики (если доступны).

Сброс пароля: ссылка на странице входа → письмо → подтверждение нового пароля.

---

## 2. Быстрый старт: кросспостинг

Типовой сценарий «собрал в Telegram → опубликовал в VK»:

1. **Brands** — создайте бренд (рабочее пространство).  
2. **Channels** — привяжите каналы/аккаунты к бренду.  
3. Откройте **Telegram** → вкладка авторизации: API id, API hash, код из Telegram (и 2FA при необходимости).  
4. В настройках профиля TG включите **сбор** и укажите чаты/каналы для чтения; включите **публикацию** и канал назначения при необходимости.  
5. В **VKontakte** настройте профиль (OAuth или токены сообщества/пользователя) и включите публикацию.  
6. В профиле источника отметьте целевые платформы (флаги вроде «в VK», «в WordPress»).  
7. Дождитесь циклов: бот собирает → **Collector** → **Processor** → **Collector** distribute → бот публикует.  
8. Контроль: **Inbox** (очередь/модерация), **Calendar**, **Analytics**.

Ручной пост без сбора: раздел **Posts** (`/posts`) — текст, медиа, выбор платформ.

| Раздел | Для чего |
|--------|----------|
| **Brands** | Бренды / проекты |
| **Channels** | Каналы и маршруты контента; карточка канала — поток |

## 4. Платформы

### Telegram
- Авторизация Telethon (код / пароль).  
- Сбор из чатов, публикация в канал/чат.  
- Обработка текста (правила / AI) в профиле.  
- При блокировке MTProto администратор может задать `TELEGRAM_PROXY_URL`.

### VKontakte
- Профиль: owner_id, права сообщества, OAuth через Gateway.  
- Сбор и публикация через vk-bot.

### Instagram / Threads / Twitter
- Учётные данные и (где нужно) Selenium-fallback — в профиле платформы.  
- Публикация из очереди `*_posts` со статусом ready.

### WordPress
- URL сайта, учётные данные / application password.  
- Сбор с сайтов и публикация статей.

### Яндекс Дзен
- Профиль + RSS для робота Дзена.  
- Сессия Яндекса через dzen-bot (диагностика скриншотов в storage при сбоях).

### Custom URL
- URL, XPath/селекторы, расписание.  
- url-bot скрапит страницы; дальше контент идёт в общий пайплайн.

## 5. Как движется пост (для понимания статусов)

1. Пост появляется в таблице платформы (`collected` / `created`).  
2. **Collector** переносит в общую `posts`.  
3. **Processor** обрабатывает (лимиты длины, HTML, AI) → `ready` или `review`.  
4. При `review` проверьте **Inbox** и подтвердите.  
5. **Collector** распределяет по целевым `*_posts` (`ready`).  
6. Бот платформы публикует → `published` (или `failed`).

Подробности для разработчиков: [POSTS_LIFECYCLE.md](POSTS_LIFECYCLE.md).

---

## 6. Модерация и AI

- В профиле платформы можно включить отправку на модерацию (`review`).  
- AI (Ollama) помогает переписывать/адаптировать текст; глобальный тоггл — **Checks → AI** (админ), плюс kill-switch `AI_ENABLED` на сервере.  
- Если AI недоступен, пайплайн обычно продолжает работу без генерации.

## 7. Типовые вопросы

**Посты не публикуются**  
Проверьте авторизацию бота, флаги публикации, статусы в Inbox/Checks → posting diagnostics, логи соответствующего `*-bot`.

**Нет превью картинок**  
Проблема с MinIO / `S3_PUBLIC_ENDPOINT_URL` — обратитесь к администратору.

**Не приходит код Telegram**  
Повторный запрос кода, проверка API id/hash, прокси.

**Нет доступа к Administration / Checks**  
Нужна роль admin.

**Справка пустая**  
Админ заполняет блоки в Administration → guide; публичная страница — `/about`.

## 8. Безопасность

- Не передавайте API hash, пароли и JWT третьим лицам.  
- Используйте выход со всех устройств при компрометации.  
- OAuth VK и редиректы должны указывать на ваш официальный домен.
