Требуется создать сервис для отображения данных в Web user interface. Из сервиса отправляются запросы на API Gateway (и отправка и получение данных).
Требуются следующие разделы:
1. Раздел регистрации со следующим функционалом
Регистрация (Sign Up): Создание нового пользователя. Требуется форма ввода со следующими полями 
- логин 
- пароль 
- email
В случае успешной регистрации, требуется перевести пользователя на страницу профиля, скрыть разделы регистрации и раздел ввода логина.  
Используется запрос с ui-app post /auth/register на сервис API Gateway
2. Раздел для ввода логина и пароля
Вход (Sign In / Login): Требуется форма ввода 
- логин 
- пароль 
В случае успеха сервис выдает страницу профиля пользователя, также в случае удачного логина требуется скрыть разделы регистрации и раздел ввода логина.
Нужна отдельная кнопка для сброса пароля (Password Reset): Запросы на инициацию сброса и подтверждение смены пароля. Используется запрос с ui-app post /auth/reset-password на сервис API Gateway
3. Раздел для работы с профилем пользователя
Требуется отразить данные профиля пользователя  форма ввода для логина, пароля.
Получение профиля (Profile): Возвращает данные о текущем пользователе на основе JWT в заголовке.
Отражение следующих данных:
- пары токенов (access_token и refresh_token) от сервиса auth.
- логин 
- пароль 
- email
Используется запрос с ui-app get /auth/profile на сервис API Gateway
В случае отсутсвия верифицированного email отражается и форма для верификации (ввод кода, отправленого на email)
Также необходима реализация возможност изменения данных профиля - форма принимает обновленные данные о текущем пользователе:
- пароль 
- email
Используется запрос с ui-app post /auth/profile на сервис API Gateway
Отдельная кнопка на отзыв всех сессий, клик по которой позволяет пользователю выйти (logout) со всех устройств сразу (удаление всех Refresh-токенов пользователя). Используется запрос с ui-app post /auth/all-logout на сервис API Gateway
Отдельная кнопка на выход (Logout): Аннулирование refresh_token в базе данных и добавление текущего access_token в «черный список» (blacklist).
Использование Используется запрос с ui-app post /auth/logout на сервис API Gateway
4. Раздел статистики (Statistics) использования сервиса (видимость только для авторизованного пользователя) 
Требуется реализация кнопки запроса healthcheck. По клику на кнопку отправлять запрос с ui-app get /core/healthchecks на сервис api-gateway
   Ответ отобразить в таблице, перечислить в строке все опрошенные сервисы, первый столбец = имя сервиса, второй столбец = результаты проверки (статус ок или ошибка) 
   Требуется реализация кнопки запроса statistic. По клику на кнопку отправлять запрос с ui-app get /core/statistics на сервис api-gateway
   Ответ отобразить в таблице, перечислить в строке все опрошенные сервисы, первый столбец = имя сервиса, второй столбец = количество собранных постов, третий столбец = количество обработанных постов, четвертый столбец = количество опубликованных постов
   Все данные требуется передавать на api-gateway post c префиксом /core/
